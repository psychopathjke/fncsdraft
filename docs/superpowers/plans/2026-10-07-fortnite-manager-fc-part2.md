# Fortnite Manager «как в FIFA» — часть 2 (механики EA FC) — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (выбран владельцем: «делай», инлайн). Steps use checkbox (`- [ ]`).

**Goal:** Скаутская сеть, молодёжные скауты, план развития, аренды и награды сезона в Fortnite Manager.

**Architecture:** Всё в `index.html` рядом с функциями `mgr*` (ветка `mgr-fc`, поверх части 1). Новое состояние — поля `MGR.*` в сейве `fncsdraft_manager`; недельные и месячные тики — из существующих `mgrWeekly` и `mgrPayMonths`; экраны — подвкладки хаба части 1 (`mgrSubTabsHTML`, `MGR_SUB`). Карточки людей, которых нет в сцене своего региона (скаут из чужого региона, выдуманная молодёжь), хранятся снимком в `MGR.ext[hKey]` и находятся `mgrCardBase` первыми.

**Tech Stack:** ванильный JS; проверка — `tools/check-mgr-hub.js` (новые секции).

**Spec:** `docs/specs/2026-10-07-fortnite-manager-fc-design.md` (раздел «Часть 2»).

## Global Constraints
- Подписи — в `mgrT9()` ru/en.
- CSS менеджера — с префиксом `#screen-manager` (иначе проигрывает клону стилей карьеры).
- Детерминизм: броски через `careerRng(ccHashStr(...))`, как весь менеджер.
- Деньги — через `MGR.club.cash`; зарплаты скаутов — в `mgrStaffWage()` (её уже вычитает `mgrPayMonths`); всё под `mgrWageRoom()` не считается (это штаб, не игроки).
- Правки `index.html` — Edit/скрипт-сплайс; не `node -e` с регулярками.

## Review Focus
1. Старый сейв без `scouts/yscouts/plan/loans/awards/ext` — хаб и все подвкладки открываются.
2. Выдуманный молодой игрок: карточка есть в составе, листе, вечере (`mgrCard` → `MGR.ext`), не теряется после `mgrNextSeason` (новый год перечитывает карточки).
3. Аренда: игрок на аренде не выходит в вечер и не попадает в команды; возвращается в запас ровно через 28 дней.
4. Скаут в регионе без людей по заданию — отчёт пустой без исключения.
5. Награды не дублируются при повторном вызове итогов сезона.

### Task 1: Карточки вне сцены + скаутская сеть
- `MGR.ext` (hKey → карточка); `mgrCardBase` сначала смотрит туда.
- `MGR_SCOUT_LV=[0,{cost:1000,width:8,n:1},{cost:2500,width:5,n:2},{cost:5000,width:3,n:3}]`, `MGR_SCOUT_MAX=3`.
- `MGR.scouts=[{id, lv, region, role:''|'roleIGL'|'roleFRG', age:0|N, min:0|N}]`; `mgrScoutHire(lv)`, `mgrScoutFire(id)`, `mgrScoutSet(id, field, value)`.
- Еженедельно (`mgrWeekly` → `mgrScoutWeek(d)`): каждый скаут берёт из `ccSceneRoster(region)` подходящих (не в клубе, роль, возраст `ccAgeOf`, рейтинг ≥ min), 1–3 по уровню, детерминированно; пишет `MGR.srep[hKey]={h, region, views:+1, lv:max, day}`, карточку в `MGR.ext`, письмо `kind:'info'` «Скаут: отчёт по …».
- Вилка потенциала (`mgrPotText`): если есть отчёт — ширина `max(1, width(lv) − 2×(views−1))`.
- «Звёзды» отчёта: текущий `mgrStarsOf(ovr)` и потенциал `mgrStarsOf(pot)` (1–5, шаг 0.5, 60→1, 95→5).
- Подвкладка Трансферы → «Скаутинг»: наём (3 уровня), список скаутов с выбором региона/роли/возраста/рейтинга, отчёты (звёзды, вилка, ★ в шортлист, «Подписать»).
- `mgrStaffWage` += зарплаты скаутов.
- Тест «скауты»: нанять, задать регион NAC, `mgrScoutWeek` 3 раза → есть отчёты из NAC, вилка сузилась, письмо есть, ставка в `mgrStaffWage`; регион без людей по заданию (min=99) — без исключения.

### Task 2: Молодёжные скауты
- `MGR.yscouts=[{id, nat}]` до 2, $1500/мес. Раз в месяц (`mgrPayMonths` → `mgrYouthMonth(m)`) каждый находит 1–2 выдуманных 15–17 лет: `careerLadderPlayer(rnd, 50..68, taken, nat, role, 99, false)` → карточка с `_youth:true, age, nat`, потенциал 70–94 (`_pot`), в `MGR.ext` и `MGR.ylist`.
- `mgrPot` уважает `_pot`; подписать — `mgrToAcad(h, true)` (бесплатно, под потолком зарплат).
- Подвкладка Клуб → «Молодёжь»: наём, страна (флаги из `careerNatPool()`), список найденных с «В академию».
- Тест «молодёжь»: нанять, `mgrYouthMonth` → 1–2 игрока 15–17, рейтинг 50–68, потенциал 70–94; «В академию» → в академии, карточка находится, лист открывается, после сохранения/загрузки цела.

### Task 3: План развития
- `MGR.plan[h]={role, since, focus}`: роль-цель — через 56 дней (`mgrPlanWeek`) `MGR.roles[h]=role` → `mgrCard` возвращает `{…card, _roleKey}`; `focus:true` — шанс роста в `mgrDevelop` ×1.5 (ruling: по атрибутам у карточек нет хранилища — упор = скорость роста).
- В листе игрока: «План: роль → …», «Упор в рост», статус «осталось N дней».
- Тест «план»: задать роль, прошагать 56 дней → `attrsFor(mgrCard(h)).roleKey` = цель; focus меняет вероятность (замер на 200 месяцах).

### Task 4: Аренды
- `mgrLoan(h)`: только запас/академия; `MGR.loans[h]={until:+28, to:клуб ниже}`; игрок снимается из команд и запаса в `MGR.loanOut`, клуб платит 50% (зарплата ×0.5 в `mgrWage` пока на аренде), рост ×1.3 в `mgrDevelop`.
- `mgrLoanWeek(d)`: истёк — назад в запас, письмо с итогом (+рост).
- В листе — «Отдать в аренду»; в Составе — плитка «В аренде».
- Тест «аренда»: отдать → нет в `mgrAll()`, зарплата половина; 28 дней → в запасе, письмо.

### Task 5: Награды
- `mgrAwardsMonth(m)`: «Игрок месяца» клуба — больше всех киллов за вечера месяца (`MGR.log` night → `kills`), письмо и `MGR.awards`.
- В `mgrSeasonReview` один раз за год (`MGR.awardYear`): «Игрок года» (киллы сезона), «Молодой игрок года» (≤19 по `ccAgeOf`/`_youth.age`), «Менеджер года» — ты, если лучшее место клуба лучше всех соперников (`MGR.rivals`), иначе лучший соперник. В `MGR.trophies`/`MGR.awards`, показ — Таблицы → «Трофеи» и Новости Центра.
- Тест «награды»: подложить вечера с киллами → месяц даёт игрока месяца; итоги сезона дважды → награды один раз.
